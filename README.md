# Модус Сигнал

MVP системы обратной связи и предложений сотрудников ГК «Модус Трейд». Сотрудник подаёт обращение, система назначает ответственного и сроки, ответственный фиксирует ход рассмотрения и результат, автор видит ответ.

## Запуск

Нужен Node.js 18 или новее; текущие проверки выполнены на Node.js 22.21.1. Внешних npm-зависимостей нет, `npm install` не требуется. Сборка не нужна.

```powershell
cd "C:\Users\arman\Desktop\озелен\modus-signal"
$env:HOST='127.0.0.1'
$env:BITRIX24_WEBHOOK_URL=''
npm start
```

Открыть http://localhost:3000. Для локальной демонстрации также можно запустить `start.cmd`. Остановка — Ctrl+C. Если порт занят, задайте `$env:PORT='3001'`. Значение HOST важно: сервер без этой настройки по умолчанию слушает все сетевые интерфейсы. Демонстрационный вход не предназначен для открытой публикации.

## Проверки

```powershell
npm test
npm run check
```

`npm test` запускает восемь тестов с проверками условий: все шесть сценариев из датасета, доступ к аналитике и CSV, внутренние заметки, защита выгрузки от формул и имитация очереди Битрикс24. Тесты создают отдельное состояние в памяти и не изменяют `data/db.json`. Проверяется сериализация состояния, но не устойчивость файловой записи при аварийном отключении.

`npm run check` проверяет синтаксис JavaScript и наличие ресурсов, подключённых в `web/index.html`. `tests/quick-api.mjs` и `tests/quick-seed.mjs` оставлены как дополнительные диагностические скрипты; они не заменяют тесты с assert.

## Реализовано

- Главная по ролям, карточки/таблица в списках, шкала этапов в обращении, светлая и тёмная темы, демо-тур.
- Проблемы, предложения и положительные отзывы; вложения до 2 МБ каждый, максимум 5 файлов.
- Категории, приоритеты, маршрутизация, замещение отсутствующих и резервный координатор.
- Статусная модель, вопросы автору, комментарии, внутренние заметки, решения и мотивированный отказ.
- Контроль сроков первого ответа и решения; отдельный срок реализации; пауза на уточнение и эскалации.
- Серверные права, публичные/непубличные обращения, псевдонимизация автора для анонимной подачи.
- Поиск, фильтры, просрочки, TF-IDF-подсказки похожих обращений, объединение дублей, поддержка идей, оценка результата.
- Аналитика, CSV, уведомления внутри приложения, доска публичных результатов, администрирование.
- Код адаптера Битрикс24: сопоставление по e-mail, уведомления и создание задач. На живом портале не проверен.

## Данные и ограничения

При первом запуске создаются `data/db.json` и `data/secret.key`. В состоянии — 40 синтетических обращений: A-001…A-020 основаны на исходном датасете, A-021…A-040 добавлены для демонстрации повторов и сложных сценариев. Заголовки, конкретные имена, даты, комментарии, оценки, решения и связи дополнены для демо; это не реальные сведения о компании. Поле `source` различает `dataset`, `extra` и `user`.

Состояние живёт в памяти и сохраняется целиком в JSON через временный файл с задержкой 250 мс. Между перезапусками данные сохраняются, но при аварии возможна потеря последних изменений. Нет транзакционной СУБД, резервного копирования и многопроцессного режима. Не запускайте два сервера с одним DATA_DIR. Для переноса используйте копию всей папки data после штатной остановки; секрет не публикуйте.

Вход — выбор пользователя без пароля, токен хранится браузером. Любой участник демо может выбрать администратора. Анонимность означает скрытие имени в интерфейсе; это не защита от оператора сервера, имеющего секрет и справочник пользователей. Открытые обращения видны коллегам, включая описание и публичную историю; файлы и внутренние заметки имеют отдельные ограничения.

Сроки в рабочих днях учитывают выходные, но не производственный календарь и праздники. Фоновые проверки работают только при работающем сервере. Первый ответ считается в календарных часах, объединённые дубли исключены из основных KPI. Аналитика и CSV доступны руководителям и администратору только по собственным обращениям и обращениям, к которым у них служебный доступ.

Без вебхука Битрикс24 и e-mail имитируются записями очереди. E-mail-отправитель и интеграция с 1С не реализованы. Настройка Битрикс24 описана в `BITRIX24.md`; живые API-вызовы и доставка не проверены. Вебхук на защите не обязателен.

Нет корпоративного SSO, отзыва/срока жизни токенов, антивирусной проверки вложений, полноценного аудита и защиты для промышленной эксплуатации. Результаты визуальной проверки предыдущей версии сообщены автором доработок; текущие изменения проверены автоматически, повторная браузерная проверка не выполнена.

## Структура и репозиторий

`web/` — интерфейс; `core/` — модель, правила, аналитика и синтетические данные; `server/` — HTTP-сервер и адаптер Битрикс24; `tests/` — проверки; `scripts/` — проверка исходников; `docs/` — материал для защиты.

Локальный Git-репозиторий существует. `data/`, секреты, журналы и архивы исключены из новых добавлений через `.gitignore`. Для сдачи команда должна создать коммит и опубликовать репозиторий в своём аккаунте; удалённый репозиторий в рамках этой работы не создавался.
